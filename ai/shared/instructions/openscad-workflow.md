# Shared OpenSCAD Workflow

Version: 1.0.0
Owner: shared
Scope: Reusable workflow for multiple coding agents in this repository.

## Purpose

Use this document as the single source of truth for OpenSCAD model generation,
validation renders, and STL export.

## Spec-Driven Workflow

Adopt a spec-driven workflow by capturing requirements before modeling.
For each model, define a specification that includes:

- objective and function of the part
- mounting or attachment method
- target dimensions and tolerances
- hardware interfaces, clearances, and fastener sizes
- material and print orientation assumptions
- support requirements and strength expectations

Use the spec to:

- choose parameter names and values at the top of `model.scad`
- drive the geometry in the first iteration
- create a short `requirements.md` or `model_spec.md` in the project folder
- validate against the spec during preview and export

## Required Project Structure

For each new model, create a dedicated project folder:

- <project>/model.scad
- <project>/model_preview_iso.png
- <project>/model_preview_side.png
- <project>/model_preview_bottom.png
- <project>/model_preview_top.png
- <project>/model_preview_print_bed.png
- <project>/model_preview_debug.png
- <project>/model.stl

The preview and export files are generated by the shared workflow/script and do not need to be created manually.

Temporary debug file (must be removed after validation):

- <project>/debug.scad

## Render Mode & Part Selector Standard

For multi-part models, ALWAYS define a standardized `part` parameter using OpenSCAD Customizer dropdown syntax near the top of `model.scad`:

```scad
/* [Render Mode & Part Selector] */
part = "all"; // ["all": Assembled View, "part1": Part1 Only, "part2": Part2 Only, "print_bed": 3D Print Layout (Z=0), "exploded": Exploded Assembly View]
```

### Standardized `part` Modes:
- `"all"`: Assembled view showing how parts fit together.
- `"part1"`, `"part2"`, etc.: Individual component views for isolating single parts.
- `"print_bed"`: All printable parts laid flat side-by-side at $Z = 0$. Every individual part MUST be evaluated and independently rotated (`rotate([rx, ry, rz])`) into its optimal FDM printing orientation.
- `"exploded"`: Exploded visual alignment view showing assembly sequence along the $Z$-axis.

## Universal FDM & CSG Modeling Rules

1. **Parameterize Key Dimensions**: Keep all key dimensions, tolerances, and hardware clearance values as variables near the top of the file.
2. **Multi-Axis Mating Clearances**: For interlocking or sliding joints (keys, slots, caps, pins), ALWAYS apply clearances in ALL active axes ($X$ radial depth, $Y$ slot width, $Z$ height). For cylindrical sliding fits ($d > 20\text{ mm}$), use a minimum diametrical clearance of $0.60\text{--}0.80\text{ mm}$.
3. **Z-Bound Safety ($Z \ge 0$)**: All part geometry and rotation transformations MUST satisfy $Z \ge 0$ across their bounding box. Never allow elements to extend into negative $Z$ space below the print bed.
4. **Per-Part Optimal Print Orientation & Collision Audit (`part == "print_bed"`)**: Do not simply layout parts in their assembly orientation. For EVERY individual part in `part == "print_bed"`, evaluate its geometry and independently rotate it (`rotate([rx, ry, rz])`) to ensure:
   - The largest, flatest face rests directly on $Z = 0$ for maximum bed adhesion.
   - Internal cavity ceilings or hollow skirts are inverted (e.g. rotated $180^\circ$) to eliminate internal bridging and support requirements.
   - Textured/debossed text faces lie flat against the PEI build plate for pristine surface finish.
   - **Universal Part Collision Audit**: Bounding box extents $[X_{min} \dots X_{max}]$ and $[Y_{min} \dots Y_{max}]$ of all parts on the print bed MUST be strictly disjoint (`intersection() { part1(); part2(); }` == empty CSG volume), leaving a minimum **$10\text{--}15\text{ mm}$ clearance gap** between adjacent parts regardless of rotation angles.
5. **Bed-Facing Surface Flatness**: In print-bed orientation (`part == "print_bed"`), resting faces on $Z = 0$ MUST be $100\%$ flat. Recess or countersink any lead-in funnels, text, collars, or bosses flush with the surface instead of letting them protrude past $Z = 0$.
6. **Grounded Vertical Features**: Outer wall alignment ridges, key tabs, or guide rails MUST extend all the way down to $Z = 0$ (or be supported by $45^\circ$ chamfers) so they build layer-by-layer directly from the build plate without mid-air overhangs.
7. **Annular Ring Subtractions around Shafts**: Recessed pockets or channels surrounding a central pin/post MUST be subtracted as hollow annular rings (`difference() { cylinder(d=pocket); cylinder(d=pin); }`) so the central post remains $100\%$ solid, round, and untouched.
8. **Full-Pass Through-Holes**: Through-holes, punch channels, and wire slots MUST extend from $Z = -0.1$ to $Z = h + 0.1$ (or beyond) to prevent accidental solid end-caps or Z-fighting.
9. **Support-Free Design**: Avoid horizontal overhangs $> 45^\circ$. Use $45^\circ$ chamfers on inner ceiling transitions and bottom edges to prevent elephant-foot distortion.
10. **Manifold Geometry**: Ensure clean CSG boolean operations without zero-thickness walls or non-manifold edges before STL export.

## Coordinate System & Rotation Conventions

OpenSCAD uses a right-handed coordinate system:

| Axis | Direction |
| :--- | :--- |
| `+X` | Right |
| `+Y` | Back / Depth (away from viewer) |
| `+Z` | Up |

### Rotation Rules

- **Reclining Backrest / Tilt Backward** (`Anlehnung nach HINTEN`):
  MUST use a **negative** X-rotation angle: `rotate([-tilt_angle, 0, 0])`.
  This tilts the top edge away from the viewer towards `+Y`.

- **Tilting Forward** (`Neigung nach VORNE`):
  A **positive** X-rotation angle `rotate([+tilt_angle, 0, 0])` tilts the top edge forward towards the front (`-Y`).

### Symmetry & Centering Rules

- When scaling or insetting a child element by `inset` on each side (`w = outer_w - 2*inset`),
  always translate it by `translate([inset, inset, ...])` or equivalently `translate([(outer_w - w)/2, (outer_d - d)/2, ...])`.
- Never leave nested geometry at `(0,0)` origin when the parent is not also at `(0,0)` — this causes asymmetric wall offsets.

### Visual Verification Requirement

After every render iteration, inspect **all** generated preview images. Each view serves a distinct validation purpose:

| File | Camera Angle | What to verify |
| :--- | :--- | :--- |
| `model_preview_iso.png` | Isometric (60°, 315°) | Overall shape, proportions, and visible geometry |
| `model_preview_side.png` | Side (90°, 90°) | **Tilt / rotation direction** — confirm backrests and stands lean backwards (`+Y`), not forward |
| `model_preview_top.png` | Orthographic top-down | Wall thickness symmetry, lip/inset centering, hole alignment |
| `model_preview_bottom.png` | Orthographic underside | Underside geometry, bridging, infill assumptions |
| `model_preview_print_bed.png` | Low-angle (120°, 315°) | Overhangs > 45°, bridging spans, print bed contact area |
| `model_preview_debug.png` | Isometric with `#` highlight | Hidden cutouts, internal intersections, Z-fighting |

**Minimum required views** before declaring an iteration complete: `iso`, `side`, and `top`.
The `debug` pass is mandatory whenever the design contains internal cutouts, recessed slots, or stacked boolean operations.

## OpenSCAD CLI

Preferred command:

- openscad

Fallback paths:

- Windows: %ProgramFiles%\OpenSCAD\openscad.exe
- macOS: /Applications/OpenSCAD.app/Contents/MacOS/OpenSCAD
- Linux: /usr/bin/openscad

## Validation Render Commands

Render from project root or workspace root with adjusted paths.

1. Isometric:

```bash
openscad --imgsize=800,600 --camera=0,0,0,60,0,315,200 -o <project>/model_preview_iso.png <project>/model.scad
```

2. Side:

```bash
openscad --imgsize=800,600 --camera=0,0,0,90,0,90,200 -o <project>/model_preview_side.png <project>/model.scad
```

3. Print-bed view:

```bash
openscad --imgsize=800,600 --camera=0,0,0,120,0,315,200 -o <project>/model_preview_print_bed.png <project>/model.scad
```

4. Debug highlight pass:

- Create <project>/debug.scad and highlight key cutouts/components with #.
- Render:

```bash
openscad --imgsize=800,600 --camera=0,0,0,60,0,315,200 -o <project>/model_preview_debug.png <project>/debug.scad
```

- Delete <project>/debug.scad after render.

## STL Export

```bash
openscad -o <project>/model.stl <project>/model.scad
```

## Review Checklist

1. **Z-Bound Check**: No geometry extends into negative $Z$ space below $Z = 0$.
2. **Bed Contact Flatness**: Resting faces on $Z = 0$ in `part == "print_bed"` are $100\%$ flat without protruding collars or bosses.
3. **Grounded Features**: Outer wall alignment ridges and keys extend down to $Z = 0$ or are supported by $45^\circ$ chamfers.
4. **Multi-Axis Clearances**: Interlocking joints have clearances in ALL 3 axes ($X, Y, Z$) with $\ge 0.60\text{--}0.80\text{ mm}$ diametrical gap on cylindrical sliding fits.
5. **Intact Central Shafts**: Pocket subtractions surrounding central posts use annular ring shapes so shafts remain solid and un-sliced.
6. **Fully Open Channels**: Through-holes, punch channels, and slots pass completely through from $Z = -0.1$ to $Z = h + 0.1$.
7. **Clean Debug View**: No unintended hidden intersections or Z-fighting in debug renders.
8. **Manifold STL Export**: STL export succeeds without geometry or manifold errors.
